# บัญชีไร่อ้อย (Sugarcane Farm Accounting)

เว็บไซต์สำหรับจดบันทึกงานและค่าแรงของคนงานในไร่อ้อย
เจ้าของไร่และผู้ดูแลใช้บันทึกว่าใครทำงานอะไร ได้เงินเท่าไร เบิกเงินล่วงหน้าไปเท่าไร
ส่วนคนงานเข้ามาดูยอดเงินของตัวเองได้ทุกเมื่อ

repo นี้คือ **ส่วนหน้าเว็บ (frontend)** ที่ผู้ใช้มองเห็นและกดใช้งาน
ข้อมูลจริงทั้งหมดเก็บอยู่ที่ **ระบบหลังบ้าน (backend)** ซึ่งอยู่อีก repo ชื่อ `aomaoi-backend`

## 1. ใครใช้ระบบนี้ และทำอะไรได้บ้าง

ระบบมีผู้ใช้ 3 แบบ แต่ละแบบเห็นเมนูไม่เหมือนกัน

### คนงาน (Worker)

| เมนู | ใช้ทำอะไร |
|---|---|
| แดชบอร์ด | ดูรายได้รวม ยอดที่เบิกไปแล้ว และ **ยอดเงินคงเหลือ** ของตัวเอง |
| ประวัติงาน | ดูว่าทำงานอะไรไปบ้าง วันไหน ได้เงินเท่าไร ค้นหาและกรองได้ |
| เบิกเงินล่วงหน้า | ดูประวัติการเบิกเงินและสิ่งของทั้งหมดของตัวเอง |

### ผู้ดูแลไร่ (Admin)

ดูแลไร่ของตัวเอง 1 ไร่

| เมนู | ใช้ทำอะไร |
|---|---|
| แดชบอร์ด | ภาพรวมของไร่ ยอดเงิน กราฟ และงานที่กำลังทำอยู่ |
| คนงาน | เพิ่ม แก้ไข ลบคนงาน และ **เช็กชื่อประจำวัน** (มา / ลา / ขาด) |
| บันทึกงาน | บันทึกงาน 4 แบบ ได้แก่ ตัดอ้อย ปลูกอ้อย รดน้ำ พ่นยา ระบบ **คำนวณค่าแรงให้อัตโนมัติ** |
| เบิกเงินล่วงหน้า | จดว่าคนงานเบิกเงินหรือของอะไรไป เท่าไร |
| สรุปบัญชีคนงาน | ดูว่าคนงานแต่ละคนได้เงินเท่าไร เบิกไปเท่าไร เหลือเท่าไร ใครติดหนี้ |

> การเช็กชื่อของวันนี้จะปิดตอน 18:00 คนงานที่ยังไม่ได้เช็ก ระบบจะบันทึกให้อัตโนมัติ

### ผู้ดูแลระบบสูงสุด (Super Admin)

ดูแลทุกไร่ในระบบ

| เมนู | ใช้ทำอะไร |
|---|---|
| แดชบอร์ด | ภาพรวมของทุกไร่รวมกัน |
| ฟาร์มทั้งหมด | เพิ่ม แก้ไข ลบไร่ |
| แอดมินทั้งหมด | สร้างและจัดการบัญชีผู้ดูแลของแต่ละไร่ |
| บันทึกระบบ | ดูย้อนหลังว่าใครทำอะไรในระบบ เมื่อไร |

## 2. วิธีใช้งานเว็บ (สำหรับผู้ใช้ทั่วไป)

1. เปิดลิงก์เว็บไซต์ (ขอลิงก์จากผู้ดูแลระบบ)
2. กรอก **ชื่อผู้ใช้** และ **รหัสผ่าน** ที่ได้รับ แล้วกด **เข้าสู่ระบบ**
3. ถ้าเข้าครั้งแรก ระบบจะให้ **ตั้งรหัสผ่านใหม่** ก่อนใช้งาน
4. ระบบจะพาไปหน้าแดชบอร์ดที่ตรงกับบทบาทของคุณเอง
5. เปลี่ยนภาษา ไทย / อังกฤษ ได้ที่ปุ่ม **TH / EN** ในแถบเมนูด้านซ้าย
6. ใช้งานเสร็จ กด **ออกจากระบบ** ที่ด้านล่างของแถบเมนู

> บนมือถือ แถบเมนูจะซ่อนอยู่ กดปุ่ม ☰ มุมซ้ายบนก่อน แถบเมนูจะเลื่อนออกมา

> ถ้าไม่ได้ใช้งานนาน ระบบอาจพากลับไปหน้าเข้าสู่ระบบเอง แค่เข้าสู่ระบบใหม่ ข้อมูลไม่หาย

## 3. เปิดเว็บบนเครื่องตัวเอง (สำหรับนักพัฒนา)

### สิ่งที่ต้องมีก่อน

- **Node.js** เวอร์ชัน 24 ขึ้นไป (ดาวน์โหลดที่ [nodejs.org](https://nodejs.org))
- **ระบบหลังบ้าน (backend) ที่เปิดอยู่แล้ว** ดูวิธีเปิดใน README ของ `aomaoi-backend`
  ถ้าเปิดตามนั้น backend จะอยู่ที่ `http://localhost:8081`

### ขั้นตอน

เปิดโปรแกรม Terminal (หรือ PowerShell บน Windows) ที่โฟลเดอร์นี้ แล้วพิมพ์ทีละบรรทัด

**ขั้นที่ 1: สร้างไฟล์ตั้งค่า** (ทำครั้งแรกครั้งเดียว)

```powershell
Copy-Item .env.example .env
```

ไฟล์ `.env` บอกเว็บว่า backend อยู่ที่ไหน ค่าเริ่มต้นคือ `VITE_API_BASE_URL=http://localhost:8081/api`
ถ้า backend ของคุณอยู่ที่อื่น ให้แก้บรรทัดนี้

**ขั้นที่ 2: ติดตั้งส่วนประกอบของโปรแกรม** (ทำครั้งแรก หรือเมื่อมีคนเพิ่ม package ใหม่)

```powershell
npm.cmd install
```

**ขั้นที่ 3: เปิดเว็บ**

```powershell
npm.cmd run dev -- --port 3000
```

**ขั้นที่ 4:** เปิดเบราว์เซอร์ไปที่ http://localhost:3000

> บน macOS / Linux ใช้ `cp .env.example .env` และพิมพ์ `npm` แทน `npm.cmd`

### บัญชีตัวอย่างสำหรับทดลอง

ใช้ได้เฉพาะตอนเปิด backend ในเครื่องพร้อมข้อมูลตัวอย่าง **ห้ามใช้บนระบบจริง**

| บทบาท | ชื่อผู้ใช้ | รหัสผ่าน |
|---|---|---|
| Super Admin | `superadmin` | `1234` |
| Admin | `demo_admin01` ถึง `demo_admin05` | `Temp1234` (เข้าครั้งแรกต้องตั้งรหัสใหม่) |
| Worker | `demo_worker01` ถึง `demo_worker20` | `Temp1234` (เข้าครั้งแรกต้องตั้งรหัสใหม่) |

### คำสั่งอื่นที่ใช้บ่อย

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run build` | สร้างไฟล์เว็บพร้อมใช้งานจริง ไว้ในโฟลเดอร์ `dist/` |
| `npm run preview` | เปิดดูไฟล์จาก `npm run build` ในเครื่อง |
| `npm run lint` | ตรวจหาจุดผิดในโค้ด |

## 4. นำเว็บขึ้นออนไลน์ด้วย Vercel

Vercel จะสร้างเว็บใหม่ให้อัตโนมัติทุกครั้งที่มีโค้ดใหม่เข้า branch `main` บน GitHub

### ตั้งค่าครั้งแรก

1. เข้า Vercel → เลือกโปรเจกต์ → **Settings** → **Environment Variables**
2. เพิ่มค่าใหม่
   - Name: `VITE_API_BASE_URL`
   - Value: `https://aomaoi-backend.onrender.com/api`
   - ท้ายลิงก์ **ต้องมี `/api`** ไม่งั้นเว็บจะเชื่อมกับ backend ไม่ได้
3. ไปที่แท็บ **Deployments** → กด **Redeploy** ที่รายการล่าสุด

### ข้อควรรู้

- **เปลี่ยนค่าใน Environment Variables แล้วต้องกด Redeploy ทุกครั้ง** ค่านี้ถูกฝังลงในเว็บตอนสร้าง ถ้าไม่ Redeploy เว็บจะยังใช้ค่าเก่า
- ไฟล์ `vercel.json` ทำให้กด refresh หน้าไหนก็ได้โดยไม่เจอหน้า 404 **ห้ามลบไฟล์นี้**

### ช่องทางอื่น

เว็บนี้รันผ่าน Docker หรือ Kubernetes ได้ด้วย ดูวิธีใน [k8s/README.md](k8s/README.md)

## 5. ทดสอบอัตโนมัติ (Cypress)

Cypress คือโปรแกรมที่เปิดเว็บแล้วกดปุ่ม กรอกฟอร์มแทนคน เพื่อเช็กว่าทุกหน้ายังใช้งานได้

ข้อมูลที่ Cypress สร้างระหว่างทดสอบจะถูกลบให้เองเมื่อทดสอบจบ ไม่ว่าจะผ่านหรือไม่ผ่าน
ถ้าการทดสอบค้างกลางทาง backend จะเก็บกวาดให้เองหลังผ่านไป 15 นาที

### ขั้นตอน

**ขั้นที่ 1: ตั้งรหัสสำหรับการทดสอบ**

เปิดไฟล์ `.env` ในโฟลเดอร์ `aomaoi-backend` แล้วใส่ `E2E_SUPPORT_KEY=` ตามด้วยตัวอักษรสุ่ม **อย่างน้อย 32 ตัว**

**ขั้นที่ 2: เปิดทั้งระบบด้วย Docker** (ฐานข้อมูล + backend + frontend รวมในคำสั่งเดียว)

```powershell
cd ..\aomaoi-backend
docker compose up --build -d
```

รอจนเปิดเสร็จ ระบบจะใช้ frontend ที่ `http://localhost:3000` และ backend ที่ `http://localhost:8081`

**ขั้นที่ 3: รันการทดสอบ**

```powershell
cd ..\aomaoi-frontend
npm.cmd ci
npm.cmd run cypress:run
```

อยากดูการทดสอบทีละขั้นบนหน้าจอ ใช้ `npm.cmd run cypress:open` แทน

### ข้อควรรู้

- ถ้าเปิด Docker จาก repo นี้แทน `aomaoi-backend` ต้องใส่ `E2E_SUPPORT_KEY` ค่าเดียวกันใน `.env` ของ repo นี้ด้วย
- บน GitHub การทดสอบจะใช้ backend จาก branch ที่ชื่อเหมือน branch ของ frontend ถ้าไม่มีจะใช้ `main` แก้ทั้ง 2 ฝั่งพร้อมกัน ให้ตั้งชื่อ branch ให้ตรงกัน
- รายละเอียดเพิ่มเติม: `aomaoi-backend/docs/shared-e2e.md`

## 6. เจอปัญหา ทำอย่างไร

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| กด refresh แล้วเจอหน้า **404** บนเว็บ Vercel | ไม่มีไฟล์ `vercel.json` ในเวอร์ชันที่ขึ้นเว็บ | เช็กว่า `vercel.json` อยู่ใน branch `main` แล้ว แล้วกด Redeploy |
| เข้าสู่ระบบแล้วขึ้นว่า **ไม่สามารถเชื่อมต่อกับเซิร์ฟเวอร์ได้** | backend ไม่ได้เปิด หรือ `VITE_API_BASE_URL` ผิด | เช็กว่า backend เปิดอยู่ และลิงก์ลงท้ายด้วย `/api` |
| แก้ `VITE_API_BASE_URL` แล้วเว็บยังไม่เปลี่ยน | ค่านี้ถูกฝังตอนสร้างเว็บ | บนเครื่อง: ปิด `npm run dev` แล้วเปิดใหม่ / บน Vercel: กด Redeploy |
| ถูกพากลับไปหน้าเข้าสู่ระบบเอง | การเข้าสู่ระบบหมดอายุ | เข้าสู่ระบบใหม่ |
| Cypress ขึ้นว่า `Set E2E_SUPPORT_KEY (32+ characters)` | ยังไม่ได้ตั้งรหัสทดสอบ หรือสั้นเกิน | ทำตาม [ขั้นที่ 1 ของการทดสอบ](#5-ทดสอบอัตโนมัติ-cypress) แล้วเปิด Docker ใหม่ |

## 7. ข้อมูลสำหรับนักพัฒนา

### เทคโนโลยีที่ใช้

React 19 + Vite · React Router v7 · Zustand · Tailwind CSS v4 · react-hook-form + zod · react-datepicker · Recharts · lucide-react · Axios

- เข้าสู่ระบบด้วย JWT ที่ได้จาก backend เก็บไว้ใน `localStorage` (key `auth-storage`)
- ทุกหน้ายกเว้น `/login` มี `AuthGuard` กั้น และกั้นตามบทบาทด้วย
- รองรับ 2 ภาษา (ไทย / อังกฤษ) ข้อความอยู่ใน `src/i18n/messages.js`

### Route ทั้งหมด

| Path | ใครเข้าได้ |
|---|---|
| `/login` | ทุกคน |
| `/dashboard` | ทุกบทบาท (แสดงหน้าต่างกันตามบทบาท) |
| `/history`, `/salary-advance` | Worker |
| `/workers`, `/workers/:id`, `/work`, `/advance-salary`, `/financial-balance`, `/overview` | Admin |
| `/farms`, `/admins`, `/audit-logs` | Super Admin |

path อื่นทั้งหมดจะถูกพาไปที่ `/dashboard`

### โครงสร้างโฟลเดอร์

```
src/
├── App.jsx           # ประกาศ route ทั้งหมด
├── pages/            # หน้าเว็บแต่ละหน้า แยกตามบทบาท (auth, worker, admin, superadmin)
├── layouts/          # แถบเมนูและกรอบหน้าของแต่ละบทบาท
├── components/
│   ├── ui/           # ชิ้นส่วนที่ใช้ซ้ำ (Button, Card, Modal, Dropdown, Pagination ...)
│   ├── auth/         # AuthGuard และหน้าต่างตั้งรหัสผ่านครั้งแรก
│   ├── attendance/   # ปุ่มเช็กชื่อ มา / ลา / ขาด
│   └── dashboard/    # ภาพแผนที่ไร่และงานบนแดชบอร์ด
├── controller/       # Zustand store ที่หน้าเว็บเรียกใช้ (เช่น useAuthStore)
├── service/          # logic ฝั่งเว็บ และ api.js (Axios ที่แนบ JWT ให้อัตโนมัติ)
├── repository/       # ฟังก์ชันเรียก REST API ของ backend
├── store/            # Zustand store อื่น ๆ (ภาษา, ข้อมูลแต่ละส่วน)
├── config/           # ค่าคงที่ (ประเภทงาน + สูตรคำนวณค่าแรง, สีสถานะ ...)
├── i18n/             # ข้อความ 2 ภาษา
├── hooks/            # React hooks ที่ใช้ร่วมกัน
└── lib/format.js     # ฟอร์แมตวันที่และตัวเลข
```

### ไฟล์ตั้งค่าการ deploy

| ไฟล์ | ใช้กับ |
|---|---|
| `vercel.json` | Vercel ส่งทุก path (ยกเว้น `/assets/`) ไปที่ `index.html` ให้ React Router จัดการ |
| `nginx.conf` + `Dockerfile` | Docker / Kubernetes ทำหน้าที่เดียวกับ `vercel.json` และส่งต่อ `/api/` ไป backend |
| `k8s/` + `scripts/` | deploy ขึ้น Kubernetes ดู [k8s/README.md](k8s/README.md) |
| `.github/workflows/` | CI บน GitHub: lint, build, สร้าง image, ทดสอบ Cypress |
